## 1. Design spec (what the code implements)

### Tiers

| Tier | Material | RPM cap (default) |
|---|---|---|
| BASE | vanilla Create | 256 (Create's `maxRotationSpeed`) |
| Allthemodium | `c:ingots/allthemodium` | 1,024 |
| Vibranium | `c:ingots/vibranium` | 4,096 |
| Unobtainium | `c:ingots/unobtainium` | 16,384 |

Cap = `maxRotationSpeed × tierMultiplier^tier`, so if a pack raises Create's cap, every tier scales with it.

Each tier has: **Shaft, Cogwheel, Large Cogwheel, Gearbox**.

### Rule 1: Speed cap (`TierRules`, `KineticBlockEntityMixin`, `OverspeedBreaker`)
- Every kinetic block entity, vanilla ones included, checks its speed against **its own tier's** cap when the
  speed changes. If it's too fast, it breaks at the end of that tick and drops itself, the way Create already does.
- A vanilla cog that gets stepped past 256 still breaks, same as today. That's the gap the tiered parts fill.
- Create's own global check in `RotationPropagator` is raised to the top tier's cap, but only inside
  that class. The creative motor, speed controller and so on keep their normal limits.

### Rule 2: Attachment (`TierRules.canLink`, `RotationPropagatorMixin`)
- A gear or gearbox only links along its axis to a shaft of **its own tier or higher**.
  A Vibranium shaft can drive an Allthemodium gear. An Allthemodium shaft can't drive a Vibranium gear.
- A link that breaks this rule simply doesn't connect (speed modifier 0). It doesn't explode.
- **My interpretation, please confirm:** cog-to-cog *meshing* is **not** tier-gated. Otherwise you could
  never gear back down from 16k RPM to drive vanilla machines. The speed cap still protects the weaker cog.
  Turn on the config `strictAttachment=false` to remove Rule 2 entirely.

### Speed glow (`GlowLevels`, `SpeedEffects`, `client/VisualSpeed` + client mixins)
- **On screen**, every kinetic part is drawn at most at `maxVisualRpm` (client config, default 256), so a
  16k RPM gear never strobes. This is cosmetic only: goggles, stress and processing still use the real speed.
- Past the base cap, tiered parts **emit real block light** through a `glow` blockstate, one step per speed
  doubling: 512→3, 1024→5, 2048→8, 4096→10, 8192→13, 16384→15. Changing glow doesn't re-trigger the
  network, because Create treats same block + same axis as kinetically equivalent.
- The clamp hooks `RotatingInstance.setRotationalSpeed` (all Flywheel visuals) plus the three non-Flywheel
  fallback renderers (`KineticBlockEntityRenderer`, `BracketedKineticBlockEntityRenderer`, `GearboxRenderer`).

### Stress
- Nothing new is needed for consumers. Create already scales a consumer's stress impact linearly with its RPM,
  so a press at 4× speed costs 4× SU. Shafts, cogs and gearboxes have no stress impact, same as in vanilla.

### Steam Redliner (`content/turbine`)
- A **3×3 multiblock that covers one whole face** of a 3×3×3 Create fluid tank: either side or the top. You place one
  item on the centre of the face, and it fills in 8 invisible `steam_redliner_structure` blocks around itself
  (the same pattern as Create's large water wheel). Placement fails if any of the 9 spots is blocked.
  Breaking any part breaks the whole thing and drops one turbine. The output shaft is in the centre of the
  outer face.
- **Visuals:** a copper and iron housing with a brass bezel and corner bolts is the core's chunk model, spanning
  the full 3×3. A separate rotor model spins at shaft speed: two staggered 8-blade stages, a brass hub and
  the shaft stub. It vents cloud particles and plays Create's steam sound while running. The models are
  generated by `tools/gen_turbine_models.py`.
- It's valid only when all of these hold:
  1. the tank is exactly 3×3×3, **and the turbine is centred on one of its faces**;
  2. all **9 blaze burners** under it are **SEETHING** (fed blaze cake);
  3. **no steam engines** are attached to the same boiler, and it's the **only turbine** on that tank. Placement
     refuses a second turbine with an action-bar message; a runtime check covers tanks merged afterwards;
  4. it can drain its water budget (default 200 mB/t).
- Output is a flat **`baselineEngines(9) × steamEngineReferenceSU × multiplier(4)`** SU (589,824 by default,
  confirmed in game) **at the same SU for every rotor**. Only the speed changes. A rotor outputs at the first speed
  step its crafting cog is needed for: one doubling past the previous tier's cap (`KineticTier.turbineRpm`).
  | Rotor | Output RPM |
  |---|---|
  | plain (untiered, `/give`) | 256 (`steamRedliner.outputRpm` config) |
  | Allthemodium | 512 |
  | Vibranium | 2,048 |
  | Unobtainium | 8,192 |
  The core counts as a part of its rotor's tier (`ITieredKinetic.getTier(state)`), so the output shaft must be
  that tier or stronger.
- `steamEngineReferenceSU` defaults to 16,384. **Check this in game:** build the equivalent 9-engine boiler,
  read the capacity with goggles, divide by 9, and set the default to that.
- Goggles show why a turbine isn't running (wrong size, misaligned, burners not superheated, no water, engines attached).
- Recipe: **8 Steam Engines around a tiered large cogwheel** (Allthemodium, Vibranium or Unobtainium). Every
  version yields the same item; the cog sets the **rotor blade colour and output speed**, which are stored as the
  `create_redline:rotor_tier` item component and the `rotor` blockstate, and is kept when the turbine is broken.
- Create-style shift tooltip (summary + 3 condition/behaviour lines) and a **Ponder scene** (press W on the
  item), listed under Create's Kinetic Sources tag. The scene schematic is exported by a GameTest:
  `./gradlew runGameTestServer -PexportPonder=true`, then copy `run-gametest/ponder_export/steam_redliner.nbt` into
  `assets/create_redline/ponder/`.

### Recipes
- **Sheets:** a Mechanical Press turns `c:ingots/<metal>` into an Allthemodium, Vibranium or Unobtainium Sheet (gated on
  `allthemodium` being loaded). Sheets are also tagged `c:plates/<metal>`, so other mods' plates work too.
- **Shafts:** a Deployer applies a sheet to a shaft to upgrade it one tier, one sheet per shaft:
  Create shaft + A sheet → A shaft → + V sheet → V shaft → + U sheet → U shaft (`recipe/deploying/`).
- Cogwheel = previous-tier cog + tier shaft + 1 ingot; Large cog = previous-tier large cog + tier shaft + 2 ingots;
  Gearbox = previous-tier gearbox + 4 tier shafts (the shafts already carry the sheet cost). Cogs use sheets instead of ingots. All of these need tier shafts, so everything goes through the
  press-and-deployer line.
- Steam Redliner = 8 Steam Engines around a tiered large cogwheel.
- Each tier crafts *from* the one below, so progression can't be skipped. Expect ATM pack devs to KubeJS these;
  keep recipe ids stable.

### Tiered belts
- These use Create's own belt (so funnels, tunnels, casings and dye all still work), with a tier stored on each
  segment's block entity (`BeltBlockEntityMixin`). **A belt's tier comes from the shafts it's built between**:
  each segment remembers the shaft it replaced, and the chain tier is the lowest pulley shaft's tier. Breaking,
  wrenching or tearing the belt down gives back those exact shafts (`BeltBlockMixin`).
- The belt breaks above its tier's cap like any shaft, and counts as a shaft for the attachment rule.
- **Items stay capped** at `belts.maxItemRpm` (default 256, hard max 480): items move speed/480 blocks per
  tick, and funnel, tunnel and processing checks only look one step ahead. Rotation passes through at full tier
  speed; texture scroll follows the item speed. Pulleys render in the tier's colours.
- Known gap: the belt slicer (cutting a belt with a wrench or connector) still hands back vanilla shafts.

### Machines at high speed
Tier caps and attachment rules only apply to **transmission** parts: blocks with no stress impact and no
capacity (shafts, cogs, gearboxes, belts, clutches...). Create's machines and generators run at whatever
speed they get and pay `impact × RPM` stress, which is vanilla Create behaviour. Each machine's own limit on
how much faster it processes (from the Create 6.0.11 source):
Deployer, Arm, Crafter and Fan stop at about 256; Press and Mixer at 512; Saw at 3,072; Millstone at 8,192;
Drill depends on block hardness; Pump has no limit.

## 2. Code map

```
src/main/java/com/createredline/
  CreateRedline.java          mod entry, CreateRegistrate instance
  tier/
    KineticTier.java            enum + cap math
    ITieredKinetic.java         implemented by every tiered block
    TierRules.java              speed-cap lookup + attachment rule (the whole rulebook)
    OverspeedBreaker.java       deferred end-of-tick breaking
  mixin/
    RotationPropagatorMixin     raise global ceiling; veto illegal links
    KineticBlockEntityMixin     per-BE speed check on setSpeed
  content/shaft|cog|gearbox     thin subclasses of Create's blocks; reuse Create BEs/renderers/visuals

  registry/                     ModBlocks, ModBlockEntities, ModCreativeTab
  config/RedlineConfig        server config (all balance knobs)
src/main/resources/
  assets/…                      blockstates/models (currently parent Create's models), lang
  data/…/recipe                 crafting recipes
```

## 3. Dev phases

### Phase 0: Get it compiling ✅ done
Builds with `JAVA_HOME=~/.gradle/jdks/eclipse_adoptium-21-amd64-linux.2 ./gradlew build`.
7 GameTests pass (`./gradlew runGameTestServer`), and they build real gear trains to check breaking, glow
and the attachment rule. Original notes, kept for reference:
1. Install a JDK 21 (Fedora/Nobara: `sudo dnf install java-21-openjdk-devel`). Gradle 8.10 doesn't support
   your system JDK 25 as a toolchain host reliably, and Minecraft 1.21.1 targets Java 21.
2. Generate the Gradle wrapper once: install Gradle (`sdk install gradle 8.10.2`, or download it) and run
   `gradle wrapper --gradle-version 8.10.2`. After that, always use `./gradlew`.
3. Fix `gradle.properties` versions (see top), then `./gradlew build`.
4. **Expect compile errors against Create's API.** I wrote the scaffold from knowledge of Create 6's
   source but haven't compiled it. Things to check first:
   - `CogWheelBlock(boolean, Properties)` constructor visibility
   - `GearboxVisual`, `OrientedRotatingVisual`, `BracketedKineticBlockEntityVisual::create` names/signatures
   - `FluidTankBlockEntity.boiler.attachedEngines` field name
   - The mixin target descriptor for `ConfigBase$ConfigInt.get()`. Run
     `javap -c -p -classpath <create jar> com.simibubi.create.content.kinetics.RotationPropagator`
5. `./gradlew runData` generates loot tables (blocks drop themselves) and mineable tags.

### Phase 1: Core mechanic works (MVP)
- `./gradlew runClient`, creative world. Gear a creative motor 256 → 512 through vanilla cogs. Vanilla breaks.
  Swap in Allthemodium cogs. They survive up to 1024 and break at 2048.
- Check Rule 2: a vanilla shaft into an ATM gear doesn't connect, a Vibranium shaft into an ATM gear does,
  and an ATM gearbox rejects vanilla shafts.
- Check the turbine: build the 3×3×3 tank on 9 burners with blaze cake and pumps, read goggles.
- Write **GameTests** (`src/test` or `gametest` package) for: overspeed break per tier, illegal link stays at 0,
  turbine capacity. Run them with `./gradlew runGameTestServer`, and add that to CI later.

### Phase 2: Art & feel
- ~~Tier textures~~ ✅ done at load time: `tools/gen_tier_palettes.py` writes colour palettes plus
  `assets/minecraft/atlases/blocks.json`, which recolours Create's own textures (no Create art is shipped, since it's ARR).
- **Large cogs:** Create's large-cog renderer and visual draw a hard-coded Create partial model. Subclass
  `BracketedKineticBlockEntityRenderer` / `…Visual` and pass tier partials, or large cogs will look vanilla.
- ~~Render-speed clamp~~ ✅ done: visual cap plus glow (see spec). Possible polish: an emissive overlay
  texture so the glow reads in daylight, and spark particles at 13+.
- ~~Turbine model~~ ✅ done: 3×3 multiblock housing plus spinning rotor, steam particles and sound.
- Ponder scenes for the turbine and the tier rules (Create addons are expected to have these; Ponder is already a dependency).

### Phase 3: Completeness
- Encased shafts/cogs per tier (register tier variants in Create's `EncasingRegistry`). Right now casings
  simply don't apply to tiered parts, so they can't be used to accidentally downgrade.
- Tiered Clutch / Gearshift / Vertical Gearbox / Chain Drive, if the pack needs them.
- Optional: turbine output RPM selectable with a scroll value (like the creative motor).
- JEI info pages; tooltips via Create's `TooltipModifier` (lang already has `.tooltip.summary` keys).

### Phase 4: Balance pass with the pack
- Run inside an actual ATM10 instance (Prism Launcher → import ATM10 → drop your jar into `mods/`).
- Tune `steamEngineReferenceSU`, water use, and recipe costs. Watch tick time at 16k RPM with
  Spark (`/spark profiler`). Rotation propagation cost doesn't depend on RPM, but contraptions and
  processing at those speeds might.

## 4. Deploy

1. **Repo & CI:** `git init`, push to GitHub, and add a GitHub Actions workflow that runs `./gradlew build
   runGameTestServer` on every push and `./gradlew publishMods` on tag `v*`.
2. **Listings:** create a CurseForge project (ATM packs are CurseForge-distributed, so this one is required)
   and optionally a Modrinth one. Put both project IDs in `build.gradle` → `publishMods`, and set
   `CURSEFORGE_TOKEN` / `MODRINTH_TOKEN` as repo secrets. Declare `create` and `allthemodium` as relations.
3. **Allow 3rd-party distribution** on CurseForge (Project settings). Packs can't include your mod without it.
4. **License:** MIT is set in `gradle.properties`. Create is MIT and Allthemodium is all-rights-reserved,
   but you only reference ATM items by tag and ship none of its assets or code, so you're clear.
5. **Getting into ATM:** the ATM team takes suggestions through their GitHub issue tracker / Discord.
   Have a stable release, a short showcase (video/gif of the turbine and a 16k RPM line), and the config
   knobs documented. Their pack devs will want to KubeJS the recipes, so keep recipe ids stable.
6. **Versioning:** `MAJOR.MINOR.PATCH` in `gradle.properties`. Bump MINOR for content and PATCH for fixes,
   and keep `CHANGELOG.md` current, because `publishMods` uploads it as the release notes.
